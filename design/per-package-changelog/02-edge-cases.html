1Root package owns the remainder

A manifest with path = "." would otherwise swallow every commit. Resolution is longest declared path wins, so a file under crates/cutver-pdk/ goes to that package, not to the root.

2Two packages, two entries

A commit touching files owned by different packages appears once in each — it is real history for both. It never repeats inside a single package.

3Deepest path, per file

Assignment is per file, then the commit is placed by the packages those files belong to. Nesting therefore resolves without a tie-break table.

4Unowned commits stay visible

Anything touching no declared manifest path — CI files, workspace docs, the lockfile — lands under Other changes. It is never dropped silently.

5No empty sections

A package with zero commits gets no heading. The absence is the signal; an empty section would read like a rendering bug.
